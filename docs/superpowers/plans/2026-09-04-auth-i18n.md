# Auth Screens Multi-Language Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a language selector to the five pre-login screens (Welcome, Onboarding, Login, Register, Phone Login) that translates their static text into English, Hindi, Tamil, Telugu, or Kannada.

**Architecture:** A React Context (`LanguageProvider`/`useLanguage`) holds the selected language code and a `t(key)` lookup function backed by five flat JSON dictionaries (one per language). Selection persists via the already-installed `@react-native-async-storage/async-storage`. A single reusable `LanguageSelector` component (a pill that opens a `Modal` list) is dropped into each of the five screens at a screen-specific position.

**Tech Stack:** React Native / Expo (existing), no new dependencies. Uses `@react-native-async-storage/async-storage` (already in `mobile/package.json`), `@expo/vector-icons` (already used everywhere), and React Native's built-in `Modal`.

**Spec:** `docs/superpowers/specs/2026-09-04-auth-i18n-design.md`

## Global Constraints

- No new npm dependencies — this must use only what's already installed.
- Only these five files get translated: `WelcomeScreen.tsx`, `OnboardingScreen.tsx`, `LoginScreen.tsx`, `RegisterScreen.tsx`, `PhoneLoginScreen.tsx`. No other screen is touched.
- `Alert.alert(...)` dialogs (validation errors, network failures) stay in English — not in scope. Only static screen text (headings, labels, placeholders, buttons, links) gets a `t()` call.
- Default language is English (`"en"`); no device-locale auto-detection.
- `t()` is a plain synchronous lookup with a fallback chain: current language → English → the raw key string. It never returns `undefined` or throws.
- `PhoneLoginScreen.tsx`'s existing plain-white visual style is NOT being redesigned in this plan — only its strings are translated and a selector is added.
- Every screen's existing logic (state, validation, mutations, navigation calls) must remain unchanged — this is a string-source swap plus one new component per screen, nothing else.

- Modify: `mobile/src/screens/WelcomeScreen.tsx`

**Interfaces:**
- Produces (used by every later task):
  - `mobile/src/i18n/languages.ts` exports `LANGUAGES: { code: LanguageCode; label: string; native: string }[]` and `type LanguageCode = "en" | "hi" | "ta" | "te" | "kn"`.
  - `mobile/src/i18n/LanguageContext.tsx` exports `LanguageProvider` (component, wraps children) and `useLanguage(): { language: LanguageCode; setLanguage: (code: LanguageCode) => void; t: (key: string) => string }`.
  - `mobile/src/components/LanguageSelector.tsx` exports `LanguageSelector({ variant, style }: { variant?: "light" | "dark"; style?: StyleProp<ViewStyle> })` — a self-contained pill + modal, default `variant="light"`.

`mobile/src/i18n/LanguageContext.tsx`:
```tsx
import { createContext, useContext, useEffect, useState } from "react";
import type { ReactNode } from "react";
import AsyncStorage from "@react-native-async-storage/async-storage";
import { LANGUAGES, type LanguageCode } from "./languages";
import en from "./translations/en.json";
import hi from "./translations/hi.json";
import ta from "./translations/ta.json";
import te from "./translations/te.json";
import kn from "./translations/kn.json";

const translations: Record<LanguageCode, Record<string, string>> = { en, hi, ta, te, kn };

const STORAGE_KEY = "app_language";

interface LanguageContextValue {
  language: LanguageCode;
  setLanguage: (code: LanguageCode) => void;
  t: (key: string) => string;
}

const LanguageContext = createContext<LanguageContextValue | null>(null);

export function LanguageProvider({ children }: { children: ReactNode }) {
  const [language, setLanguageState] = useState<LanguageCode>("en");

  useEffect(() => {
    AsyncStorage.getItem(STORAGE_KEY).then((stored) => {
      if (stored && LANGUAGES.some((l) => l.code === stored)) {
        setLanguageState(stored as LanguageCode);
      }
    });
  }, []);

  const setLanguage = (code: LanguageCode) => {
    setLanguageState(code);
    AsyncStorage.setItem(STORAGE_KEY, code).catch(() => {});
  };

  const t = (key: string): string => translations[language]?.[key] ?? translations.en[key] ?? key;

  return <LanguageContext.Provider value={{ language, setLanguage, t }}>{children}</LanguageContext.Provider>;
}

export function useLanguage(): LanguageContextValue {
  const ctx = useContext(LanguageContext);
  if (!ctx) throw new Error("useLanguage must be used within LanguageProvider");
  return ctx;
}
```
